## 0. 一句话概述

全站收敛为**唯一一个「新建」入口**；进入后先填**基本信息页**（访谈主题 → 受访者姓名 → 描述信息 → 场景选择），校验通过后按**「实时访谈」/「音频上传」**分流，两条路径都复用已填信息、不再重复采集。

## 1. 目标与非目标

### 1.1 目标

1. **收敛入口**：全站不再出现第二个「新建」入口。现状首页并列两个 CTA（「新建访谈（含提纲生成）」`home-dashboard.tsx:78-84` → `/projects/new/outline`；「新建访谈项目」`:86-89` → `/upload`），须合并为 REQ-16 首页「新建」分区的单一入口。
2. **基本信息前置**：进入后先到基本信息页，字段顺序 访谈主题 → 受访者姓名 → 描述信息 → 场景选择（见 §4）。
3. **分流**：校验通过后选「实时访谈」（→ REQ-14 访谈控制台）或「音频上传」（→ 现有上传链路）。
4. **信息不重复采集**：从首页新建进入基本信息页后，后续分流页面不得再要求填写项目名 / 受访者 / 采集场景（对齐验收草案）。
5. **草稿可回填**：基本信息页字段须能被 REQ-15 草稿箱回填（§7）。

### 1.2 非目标

- 不重做上传页三步向导（`interview-upload-form.tsx:76-80`：基础信息 / 采集路径 / 音频与提交）与访谈控制台（REQ-14 已交付）。
- 不做首页三区 IA 与旧路由 `/upload`、`/projects/new/outline` 的去留裁决（归 REQ-16）。
- 不做草稿箱的存储实现与清理策略（归 REQ-15）。
- 不做音频二进制入本地存储、不做字段清单的最终拍板（前置调研，见 §10）。

### 1.3 与相邻需求的边界

| 需求 | 负责 | 不在本条范围 |
| --- | --- | --- |
| REQ-16 | 首页三区 IA、旧路由裁决、卡片显式按钮与阶段展示 | 新建三步流程 |
| REQ-15 | 草稿存储 / 保留策略 / 清理 | 「基本信息页需要有草稿态」这件事本身 |

## 3. 目标流程

```
[首页「新建」单一入口]（REQ-16 三区之一）
        │
        ▼
[基本信息页]  访谈主题 → 受访者姓名 → 描述信息 → 场景选择
        │  校验通过
        ▼
[提纲步骤]  （流程内的一步，可跳过）
        │
        ▼
[分流选择]  AI 实时访谈 ／ 上传音频
        │
        ├── 选「上传音频」─────────────────────────► [现有上传链路，预填基本信息]
        │                                              /upload（或 REQ-16 裁决后的新路由）
        │
        └── 选「AI 实时访谈」
                 ├── 已有提纲 ────────────────────► [REQ-14 访谈控制台]
                 │                                     /projects/{id}/interview
                 │
                 └── 无提纲 ──► [引导弹窗：需先补填提纲]
                                     │  点击「去补填」
                                     ▼
                               [回到提纲步骤补填] ──► 补填后重新分流
```

- 基本信息页须有**稳定的字段 id**（建议沿用 `#projectName` / `#intervieweeName` / 描述信息 / `#collectionScenario` 口径），便于上传页预填与 CDP 断言。
- 「校验通过」的最小口径：必填字段非空（默认沿用现网最小必填 = 访谈主题 + 受访对象姓名；最终清单见 §10 ①）。
- 「提纲」是流程内的**可选步骤**（非前置强制条件）：跳过提纲不影响进入分流；仅当在分流页选择「AI 实时访谈」且当时无提纲时，才触发引导回填（见 §5.3）。

## 5. 分流规则

流程定位：**基本信息 → 提纲（可跳过）→ 分流（AI 实时访谈 / 上传音频）**。提纲是流程内的可选步骤，不是进入分流的前置强制条件；仅在「选 AI 实时访谈」时校验提纲存在性（§5.3）。

### 5.1 实时访谈分支

- 目标：`/projects/{id}/interview` → `src/app/projects/[projectId]/interview/page.tsx` → `InterviewConsole`。
- 建项目入口：`POST /api/projects/ai-interview`（`collectionPath="ai_interview"`，此刻无音频）。
- 进入前置条件：**须有提纲**（技术依据见 §5.3）。无提纲时不直接进入，改为引导回填（§5.3）。
- **与「提纲可跳过」的关系**：提纲是流程内可选步骤，**跳过提纲不影响到达分流页**；提纲门禁只在「选 AI 实时访谈」这一动作上生效。
- **旧读法裁决**：原「读法 A / 读法 B」二选一已按产品方口径定稿为「提纲可跳过 + 无提纲时引导回填」，不再保留待选项（见 §10 ⑤）。

### 5.2 音频上传分支

- 目标：现有上传链路（`/upload`，或 REQ-16 裁决后的新路由）。
- 基本信息页已填字段须**预填**上传页步骤一，且不再要求重复填写项目名 / 受访者 / 采集场景。
- 复用机制参考既有「提纲 → 上传」的 `sessionStorage` 标记位方案（`outline-session.ts` 的 `OUTLINE_SESSION_STORAGE_KEY` / `OUTLINE_FLAG_PARAM`）：建议把「基本信息草稿」纳入**同一套会话结构**，避免第二条 `sessionStorage`（对齐 REQ-15「会话存储结构应对齐 REQ-13 P1，避免两套」）。
- 上传页步骤二「采集路径」现有 `ai_interview` 禁用占位（`:741` / `:765-768`）在分流落地后应重新裁决去留（本条不强制改，归 §6 / §11）。

### 5.3 分流校验规则（新增）

| 分流选择 | 是否校验提纲 | 行为 |
| --- | --- | --- |
| AI 实时访谈 | 是 | **有提纲** → 直接进入访谈控制台；**无提纲** → 弹窗 / 提示信息引导用户回到提纲页补填，点击后跳转流程内提纲步骤 |
| 上传音频 | 否 | **不要求提纲**，直接进入上传链路 |

- **技术依据**：`POST /api/projects/ai-interview` 现行实现强制 `outlineDraftMarkdown` 非空（`src/app/api/projects/ai-interview/route.ts:137-139`）—— 无提纲无法建项目，故「AI 实时访谈」方向必须存在提纲。
- **提纲是流程内的一步，不是前置强制条件**：跳过提纲不影响到达分流页，也不影响「上传音频」分支；门禁只作用在「选 AI 实时访谈」这一个动作上。
- **引导文案（建议，待产品方定稿）**：「AI 实时访谈需要先有访谈提纲，请先补填提纲后再开始。」
- 引导**复用流程内同一个提纲步骤**，不新建第二条提纲链路。

## 9. 验收要点

1. 全站不再出现第二个新建入口（首页仅一个「新建」CTA；旧路由按 REQ-16 裁决后不再作为入口暴露）。
