# 技术交接说明（README）

> 面向接手本项目的工程师。目标：看完这份文档能在本机把项目跑起来，并明确什么能改、什么不能碰。
> 产品现状与排期（面向非技术读者）见 `docs/系统现状与路线图.md`。最后更新：2026-10-06。

## 一、项目概况

| 项 | 内容 |
| --- | --- |
| 技术栈 | Next.js 16.1.7 + React 19.2.3 + TypeScript + Tailwind CSS v4 |
| 移动端基准 | iPhone SE 375×667（下限）；iPhone 14 / 15 390×844（主力） |
| 数据存储 | 单文件 JSON（`storage/projects.json`），仅开发环境使用 |

## 二、快速启动

```bash
npm install
npm run dev        # http://localhost:3000
```

- 首次打开会跳登录页，先注册一个账号（邮箱 + 密码）再使用。
- 根目录 `.env.local` 已含本机所需配置，不要删除、不要提交。
- 重启 dev server：用 `Start-Process` 启动并把输出重定向到文件（如 `dev.log`）；直接 `taskkill /T` 会留下 EPIPE worker，之后会出现随机 500。

## 四、Commit 规范

- 验收全绿 → 回报结果 + diff → **等总管明确放行** → 才 commit。
- 涉及用户交互或视觉体验的改动，自动化验收通过后**必须人工测试**（自动化测不出手感与观感）。
- 不 push，由总管决定推送时机。

## 六、硬性约束（违反会导致 build 失败或测试红）

1. 不引入新 npm 依赖。
2. `globals.css` 零布局改动。
3. 不加 `!important`（全库维持 0 条）。
4. `paper-panel` 类不得作为 `position: fixed` 元素的祖先。
5. 不改数据层 / 存储层 / 导出 API。
6. `src/lib/` 保持扁平；路由文件之间不互相 import。

## 七、常见陷阱

- **`paper-panel` + `fixed`**：`paper-panel` 带 `backdrop-filter`，会创建新的 containing block，使内部 `fixed` 元素失效；需要固定定位的浮层必须 `createPortal` 到 `document.body`（参考 R5 修复）。
- **`pb-[env(safe-area-inset-bottom)]` 不得放进 `calc()`**：CSS 会静默失效，看不到任何报错。
- **Tailwind 类名不要写在注释里**：注释中的类名会被扫描并生成对应 CSS。
- **dev server 随机 500**：先看 `dev.log` 里有没有 `WorkerError` / `EPIPE`；有该签名就重启 dev server，**不要改代码**。
