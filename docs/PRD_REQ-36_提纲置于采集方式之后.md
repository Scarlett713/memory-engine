## 1. 现状描述（含问题）

### 1.1 当前步骤顺序

`src/components/new-project/new-project-flow.tsx` 的 `NEW_PROJECT_STEPS`（约 L19-23）固定为：

```
basic（基本信息） → outline（提纲） → route（选择方式）
```

即用户先填基本信息、再生成 / 编辑提纲、最后才选择「AI 实时访谈」或「上传音频」。

### 1.2 600ms 自动生成的触发逻辑

`src/components/outline/outline-plan-workspace.tsx:179-204` 的自动生成 effect：embedded 挂载且 `initialTopic` / `initialSubject` 非空时，延时 600ms 自动调用 `handleGenerate()`；`autoGeneratedRef` 兜住 StrictMode 重放与「落地即点跳过」两种情况。它是提纲步「进即生成」体验的来源，也是重排后「往返覆盖」风险（R1）的根因所在。

### 1.3 四个核心问题

1. **顺序与用户心智相反**：用户先要决定「怎么开始」（AI 访谈 vs 上传录音），提纲只是 AI 访谈的准备工作；现行顺序逼用户在选择方式之前先面对提纲，上传用户被强制白走一遍提纲步。
2. **上传路径死成本**：上传音频根本不需要提纲，却必须经过 outline 步（`/projects/new?step=outline`）才能到达 route 步再进 `/upload`，是纯浪费。
3. **弹窗是补丁**：`route-chooser.tsx:28-121` 的 `OutlineRequiredDialog` 是为「AI 分支必须有提纲」打的补丁——用户在 route 步选了 AI 却因无提纲被弹窗拦回 outline。把 outline 挪到 route 之后，这个补丁整体不再需要。
4. **建项逻辑错位**：`POST /api/projects/ai-interview` 的建项逻辑（读 `readOutlineDraftSession()`、发请求、跳 `/projects/{id}/interview`）住在 `route-chooser.tsx` 的 `handleRealtime` 里，而非流程容器 `new-project-flow.tsx`。重排后建项时机从「route 步」变为「outline 步之后」，建项逻辑必须迁移到容器。

## 2. 目标流程

### 2.1 两条路径

- **AI 访谈路径**：`basic → route → outline → 建项 → /projects/{id}/interview`
- **上传音频路径**：`basic → route → /upload?outline=1`（跳过 outline）

### 2.2 步骤条

```
01 基本信息 / 02 选择方式 / 03 提纲
```

### 2.3 设计要点（含四项裁决口径）

- **Q1（裁决：隐藏）**：AI 路径「跳过」按钮在 embedded 下**隐藏**，不保留禁用态——重排后 outline 是 AI 分支的必经步，不能跳过；实现 `{embedded ? null : <跳过按钮>}`。
- **Q2（裁决：加）**：`OutlinePlanWorkspace` 新增 `initialMarkdown?: string` 种子——防「提纲往返被重复生成覆盖」（Pi 扫描 R1）；有种子时 `markdown` 初值 = 种子、`phase = "outline"`、`autoGeneratedRef.current = true`（跳过自动生成）。
- **Q3（裁决：加）**：`handleUpload` 前清空草稿 markdown——防「旧提纲串进上传路径」（Pi 扫描 R2）；`saveOutlineDraftToSession("", readOutlineDraftSession()?.profile)` 后再 `router.push("/upload?outline=1")`。
- **Q4（裁决：方案 A｜redirect 回 route）**：不加 `intent=ai` URL 参数。`?step=outline` **冷启动**（刷新 / 直入 / 老书签 307 跳板）时，挂载 effect 内先从草稿回填 `basicInfo`，再 `goToStep("route")`（内部用 `router.replace` 同步 URL —— 只 replace 不会改本地 `step` state，必须走 `goToStep`），**不停留在 outline 步**；用户在 route 步重新选择「AI 实时访谈」。理由：outline 已是 AI 分支的终局步，脱离「已选 AI」这一前提不该独立存在；URL 也不承载意图标记，避免新参数污染既有 `?step=` 契约（探针按 `?step=outline` 断言）。

## 3. 改动范围（文件 + 行号 + 具体改什么）

### 3.1 new-project-flow.tsx（步骤顺序、跳转、建项函数迁移、回填 effect、handleBack、outline 步 props）

- `NEW_PROJECT_STEPS` 重排：`basic → route → outline`（约 L19-23）。
- `persistBasicInfo` 的 `onNext` 落点：`goToStep("outline")` → `goToStep("route")`。
- 新增 `createAiInterviewProject()`：从 route-chooser 迁移建项逻辑——读 `readOutlineDraftSession()` 取 `outlineMarkdown` + `profile`，`POST /api/projects/ai-interview`，成功 `router.push('/projects/{id}/interview')`。
- outline 步 `onContinue` 改为调用 `createAiInterviewProject()`。
- route 步 props：`onSelectAi={() => goToStep("outline")}`，删除 `onBackToOutline`。
- `handleBack`：`basic → /`；`route → basic`；`outline → route`。
- 冷启动回填 effect：**条件不放宽到 outline —— 仍只有 `initialStep === "route"` 触发回填**（BUG-16 约束：必须在 `useEffect` 内，不得在渲染期读 sessionStorage）。
- 冷启动 `?step=outline` 归一口径（Q4 裁决 · 方案 A）：同一挂载 effect 内，`initialStep === "outline"` 时**先按草稿回填 `basicInfo`（复用 route 分支的那一段回填代码），再 `goToStep("route")`**（其内部 `router.replace` 同步 URL；**不能只写 `router.replace`** —— 那不改本地 `step` state，页面会停在 outline），不渲染停留于 outline 步。
- 新增 `isCreating` / `outlineError` state，outline 步渲染错误条。
- 新增 state：`const [outlineSeed, setOutlineSeed] = useState("")`（Q2 种子）。
- `onSelectAi` 的**点击事件里**（非渲染期，避免 BUG-16 hydration mismatch）执行：
  `setOutlineSeed(readOutlineDraftSession()?.outlineMarkdown ?? "");`
  `goToStep("outline");`
- 渲染时 `<OutlinePlanWorkspace initialMarkdown={outlineSeed} … />`。**禁止写成渲染期 `readOutlineDraftSession()`，也禁止用 effect 后补再下传**：workspace 的 `markdown` 是 `useState`，prop 只在首帧被消费，后到的种子永远不生效。

## 6. 风险 / 注意事项

- **R1（高）｜提纲往返覆盖**：route → outline 往返时，提纲步 600ms 自动生成会用新生成结果覆盖用户已编辑提纲。→ **Q2 已裁决加 `initialMarkdown` 种子**（`autoGeneratedRef = true` 跳过自动生成，`markdown` 初值 = 种子）。
- **R2（高）｜旧提纲串进上传路径**：用户先走 AI 路径生成提纲、退回 route 改选上传时，草稿里残留旧提纲会随 `?outline=1` 串进上传页。→ **Q3 已裁决：`handleUpload` 前清空 markdown**。附注：`saveOutlineDraftToSession("", profile)` 会把 `readiness` 从 `drafting` 降为 `collecting`（`outline-session.ts:159`），上传页不读该字段，**无副作用**。
- **R3（高）｜探针重设基线暴露面**（P1 修订，原稿低估，以本条为准）：
  - `verify-phase3.mjs`：`[data-step-next="outline"]` 点击断言 **11 处**（L229/273/334/503/530/569/648/718/907/948/996）→ 锚点改 `"route"` 后全部失灵，需逐条更新；`data-route-modal` 弹窗断言 **6 处** → 删除；`#new-step-outline` 前置假设 **14 处** → 逐条复核语义（步骤顺序已变，凡按「basic → outline → route」写的用例都要重看）。
  - `verify-phase2.mjs`（原稿未提及）：`[data-step-next="outline"]` 点击 / 存在性断言 **4 处**（含 L171/177/239/365）→ 同步更新；`data-route-modal` 弹窗断言 **2 处** → 删除。
  - 口径澄清：phase3 全文件 **81 处** step / 分流相关命中，其中弹窗锚点 **8 行**（phase3 六处 + phase2 两处）；原稿误写作「`tmp/verify-phase3.mjs:81`」，那不是行号。
  - 对策：S6 重设清单 = phase3 **11 处点击** + phase2 **4 处** + 两文件共 **8 处弹窗断言** + phase3 **14 处前置假设复核**。
- **R4（中）｜刷新 `?step=outline` 一律回 route**：不加 `intent=ai` 参数（Q4 · 方案 A），刷新 / 直入 `?step=outline` 会在 effect 内回填 `basicInfo` 后强制回到 route 重选——行为是**确定性 redirect**，不是「尽量兼容」；用户此前在提纲步的编辑若未点「确认」不会保留（`markdown` 只在确认时落盘）。
- **R5（中）｜回填 / 重定向 effect 的 hydration 与闪现风险**：回填条件收紧为「只有 `route` 触发回填」，`outline` 改为「回填 + `router.replace` 到 route」后，仍必须守住 BUG-16 约束（全部在 `useEffect` 内、不在渲染期读 sessionStorage）；且 `?step=outline` 会在 redirect 前闪一帧 `#new-step-outline`，探针若只等锚点出现会**假通过**，S6 须改为「等 URL 变为 `step=route`」。
- **R6（中）｜src/lib/** 冻结面**：本需求不得新增 `src/lib/` 导出、不得触碰 `writing-rules.ts`（REQ-14 探针锁定）、api 层契约不放松；建项仅做调用方迁移。
- **R7（低）｜outline-plan-workspace 多宿主**：独立路由（307 跳板）与非 embedded 宿主行为须零变化（`initialMarkdown` 默认 `undefined`、`embedded` 默认 `false` 时与改前逐字一致）。
- **R8（低）｜route-chooser 探针锚点**：`#route-chooser-realtime` / `#route-chooser-upload` / `data-route` 逐字保留，不得因重构误改。
