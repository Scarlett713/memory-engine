### 一句话定位

用「语音聊天式 AI 访谈」把老人的口述人生，自动结构化成带插图的回忆录，并让子女远程参与共创，最终沉淀为可传家的数字/实体记忆资产。

### 六大功能模块

① AI 访谈式引导（动态追问）
② 全语音录入 + 实时转写
③ 人生地图（结构化大纲）
④ 写作助手（对话聚类→成文+插图）
⑤ 家庭共创（点赞/评论/补图）
⑥ 多形态产出（故事卡/书/PDF/纸质/衍生品）

## 二、技术架构 & 用户旅程（逆向推断）

### 2.1 技术栈推断（来自创始人访谈）

- **语音通信层**：早期用 RTC「实时语音打电话模式」→ 因延迟对老人不友好，**改为自研级联架构**（点击开始/结束录音 → ASR → LLM → TTS），放弃黑箱实时语音模型。
- **ASR（语音转写）**：优先选型「方言识别能力突出」的厂商，持续 A/B 对比；这是老年口音场景的生死线。
- **LLM（生成）**：**特意调低 Temperature**——记忆场景用户对虚构容忍度极低，要平实非虚构，只做轻微修辞润色。
- **TTS（语音播报）**：音色追求自然、亲和、接近真人，用于建立老人信任感。
- **写作 Agent**：对话结束后接收完整记录 → 主题聚类 → 撰写成 600–800 字结构化故事 + 同步生成插图。
- **评测系统**：内部自建维度打分（含「共情能力」），换模型/调 Prompt/改工程后量化对比。
- **存储/隐私**：加密私人空间；**离线可录音+本地编辑，联网后云端同步**；支持导出 MP3。

## 四、工程拆解 → 对「记忆引擎」的启示（重点）

下面每一条都是小鹿光年踩过/想清楚的工程决策，对应你记忆引擎可借鉴或规避的点。带 ⚠️ 的是我认为**最值得你抄作业**的设计。

| 小鹿光年的做法 | 对记忆引擎的启示 |
| --- | --- |
| ⚠️ 放弃实时语音黑箱，自研「点击开始/结束」级联架构（ASR→LLM→TTS） | 如果记忆引擎有语音交互，**不要迷信实时语音模型的"无缝"**。老人/用户把"等待"理解成"我操作错了"。用显式发送 + "思考中"状态把延迟变成可解释的仪式感。这是 UX 防焦虑的经典解法。 |
| ⚠️ 记忆场景刻意调低 Temperature，追求平实非虚构 | 记忆/回忆类内容，**用户对"编造"零容忍**。生成层要优先保真而非文采。你的记忆引擎若涉及"把记忆整理成文字/摘要"，同样要设事实底线，只做轻微润色。 |
| ⚠️ 「内容单元 = 故事卡片（文字+图片）」最小抽象 | 把记忆拆成可独立、可重组的最小单元，而非一坨长文。卡片既可汇成"书"，也可拼成时间线/月历/相框。**你记忆引擎的数据模型应从"卡片/片段"起步**，而不是从"成品文档"起步。 |
| 「人生地图」= 结构化大纲（童年/求学/事业…主题分段） | 给记忆一个**预置骨架 schema**，而不是空空白板。骨架降低用户启动阻力，也方便后续检索。你的引擎可以设计类似的"记忆维度/时间轴模板"。 |
| 动态追问：内置题库 + 结合上下文的 agent 追问 | 记忆采集不能只靠用户主动写。**主动追问/采访式采集**能挖出深层记忆。你的引擎若做"记忆助手"，追问策略（context-aware）是关键差异点。 |
| 共情能力是评测第一维度（接住情绪、温和引回） | 记忆常伴随情绪。**评测体系要单列"情感安全"维度**：不放大悲伤、不踩雷。建议你在记忆引擎里也建一套自己的质量评测问卷。 |
| 家庭共创：多角色空间（使用者≠付费者） | 记忆是关系性的。如果记忆引擎面向家庭/多人，**要设计"协作空间 + 多角色权限 + 实时通知"**，而非纯个人笔记。 |
| Local-first：离线可录可编，联网同步 | 记忆随时可能产生（走路、没网）。**本地优先 + 后台同步**比"必须联网才能用"体验好得多，也更符合隐私预期。 |
| 方言 ASR 优先选型 + 持续 A/B | 若你的用户含口音/方言，ASR 选型的"方言能力"应作为硬指标，并建立**持续对比测试**流程，而非一次性选定。 |
| IP 形象边界：不用太像真人的"小朋友"，防老人过度移情 | 拟人化要有度。记忆引擎若有人格化角色，**要明确"我是工具不是人"**的边界，避免伦理/依赖风险。 |
| 隐私：加密私人空间 + 可导出自证（MP3 导出案例） | 记忆是极高敏数据。**加密存储 + 用户可完整导出/删除**是信任前提，也是合规底线。 |
