## 0. 一句话概述

首页按创作者中心范式收敛为**「新建 / 草稿 / 历史项目」三区 + 账户区**；全站只保留一个「新建」入口（REQ-21 落地）；历史项目卡片改为**显式按钮**进入处理台并展示**当前阶段**；两条旧路由 `/upload`、`/projects/new/outline` 按 §5 裁决去留。

## 1. 目标与非目标

### 1.1 目标

1. **三区 IA 重塑**：首页由「header 双 CTA + 平铺列表」改为三区结构（§3），对齐微信创作者中心范式。
2. **唯一新建入口**：首页「新建」区是 REQ-21 流程的**唯一入口**，全站不再出现第二个新建 CTA（现状见 §2.1）。
3. **草稿区对接**：首页「草稿」区对接 REQ-15 草稿箱（§3.3 / §7）；REQ-15 未到位时以空态 / 占位承载。
4. **历史项目区承接**：原顶层平铺列表（`recent-project-list.tsx:73-86`）迁入「历史项目」区，承接 REQ-11 滚动恢复（§3.4 / §3.6）。
5. **卡片入口形态**：处理台入口为**显式按钮**（已拍板），卡片本体不做整卡可点（§4.1 / §4.3）。
6. **阶段展示**：卡片展示 `workflow` 当前阶段，复用 `project-workflow-board.tsx:23-27` 状态映射（§4.2）。
7. **账户区归属**：现有 header 账户槽位（身份标识 + 退出）在三区结构下归入「账户区」（§3.5）。
8. **旧路由裁决**：`/upload`、`/projects/new/outline` 的去留按 §5 执行（**建议口径，待产品方拍板**）。
9. **回归可控**：三个既有 CDP 脚本保持通过（重构后同步更新断言，不得删断言，§9-9）。

### 1.2 非目标

- 不重做新建三步流程本身（基本信息页、提纲步骤、分流规则、字段清单、校验口径）—— 全部归 **REQ-21**（见 `docs/PRD_REQ-21_新建流程统一.md` 全文）。
- 不做草稿的存储实现、保留时长与清理策略 —— 归 **REQ-15**（本条只声明「草稿区需要什么样的接口」）。
- **不做后台编辑管理入口**（工作人员跨账号查看 / 编辑 / 审核脱敏）—— 归 **REQ-17**；本条不在首页为其预留入口位（若需预留，见 §10 ⑤）。
- 不做上传页三步向导与访谈控制台的重做（分别归 REQ-21 / REQ-14）。
- 不改数据层 / 存储层 / 既有 API 契约；不引入新依赖、不新增色值。
- 不做首页整体视觉改版（沿用现有 `paper-panel` / `surface-card` / `section-eyebrow` 等既有 token 与组件）。

## 3. 目标信息架构（IA）

### 3.1 分区结构

```
┌──────────────────────────────────────────────────────────┐
│  账户区（§3.5）  [身份标识 · 版本]                   [退出] │
├──────────────────────────────────────────────────────────┤
│  ①「新建」区（§3.2）                                       │
│     单一 CTA ──► REQ-21 新建流程（基本信息 → 提纲 → 分流）  │
├──────────────────────────────────────────────────────────┤
│  ②「草稿」区（§3.3）                                       │
│     草稿卡片 / 空态 ──► REQ-15 草稿箱                      │
├──────────────────────────────────────────────────────────┤
│  ③「历史项目」区（§3.4）                                   │
│     原列表下沉至此；卡片：状态 + 当前阶段 + 显式按钮 + 删除  │
└──────────────────────────────────────────────────────────┘
```

### 3.2 新建区

- 内容：一个主 CTA（建议文案「新建访谈」，最终文案待定，见 §10 ②），指向 REQ-21 的入口路由（`/projects/new`，以 REQ-21 定稿为准）。
- **唯一性硬约束**：全站不得再出现第二个「新建」入口；现状两处 CTA（§2.1-1）须收敛为一处。
- 本区不含字段与校验（那是 REQ-21 基本信息页的职责）。

### 3.3 草稿区

- 承载 REQ-15 草稿箱：列表 / 卡片 + 「继续填写」入口 + 草稿态回填（对齐 REQ-15 目标范围与验收草案）。
- **本条不定义**存储位置、保留与清理策略、是否含音频二进制（归 REQ-15）。
- REQ-15 PRD 未出前，本区以**空态 / 占位**呈现（如「暂无草稿」）；不得为赶工期自建第二套 `sessionStorage`（对齐 `docs/需求登记表.md:202` / REQ-21 §5.2）。

### 3.4 历史项目区

- 承接原顶层列表（`recent-project-list.tsx:73-86` 的面板）整体下沉为该区内容。
- 保留既有滚动恢复（§2.2 / §3.6）与删除能力。
- 卡片规格见 §4。

### 3.5 账户区

- 归属：现有 header 账户槽位（身份标识 = email + 版本；退出按钮）从「header 工具栏」明确为「账户区」，**功能与行为不变**（`home-dashboard.tsx:53-76`）。
- 现有 47px 定高占位（防徽标异步到货导致 header 跳高）随 IA 调整**须重新核算**（属实测项，见 §9-8 / §10 ⑥）。
- **REQ-17（后台编辑管理入口）不在本条范围**：本区**不**为后台管理预留入口位；若 REQ-17 需要，回到本条补充设计（§10 ⑤）。

### 3.6 响应式与滚动

- 375px：单列文档流，三区纵向排列；header 不得横向溢出（沿用 `measure-375.mjs` 的度量诉求）。
- 桌面 / xl：保持现有 `xl:h-dvh xl:overflow-hidden` + 分区内部滚动的体例（`home-dashboard.tsx:22-23`）。
- 滚动恢复：`HOME_SCROLL_STORAGE_KEY` 的持久化载体由「整页列表容器」改为「历史项目区容器」（`persistPath` 仍为 `/`），对用户的恢复行为不变。

## 4. 历史项目卡片设计

### 4.1 处理台入口 = 显式按钮（已拍板）

- 现状次要链接「打开」（`recent-project-list.tsx:149-155`）**提升为卡片内的显式按钮**（主 / 次按钮样式按现有 token 选取，不新增色值）。
- **不做整卡可点**：卡片本体不绑定 click 跳转，无整卡热区。
- 对齐登记表 `:216`「已拍板（2026-10-03）：采用『显式按钮』，不做整卡可点」。

### 4.2 当前阶段展示

- 卡片须展示 `project.workflow` 的**当前阶段**（进行中的那一步），复用 `project-workflow-board.tsx:23-27` 的 `statusMap`（completed 已完成 / in_progress 进行中 / pending 待处理），并沿用 `manual_review + in_progress → 待您审校` 的口径（`:73-76`）。
- 与现有 `StatusBadge`（项目级状态）并存：状态 = 项目维度，阶段 = 流程维度，二者不互相替代。
- 展示粒度（仅显示当前一步，或「当前步骤 + x/y」并列）见 §10 ④。

### 4.3 卡片禁止项（验收即断言）

- 无整卡 `click` 热区；
- 无可点击暗示（如 `cursor-pointer`、整卡 hover 上浮）；
- 处理台入口必须是可聚焦的显式按钮 / 链接控件。

### 4.4 其它动作

- 删除能力保留（`:156-168`），交互与确认文案不变。
- 卡片其余信息（建档时间、进度计数 / 进度条）按现行保留，避免超出本条范围。

## 5. 旧路由裁决（建议口径，待产品方拍板）

- **建议：保留（作为上传链路的实现路由），但降级为非入口。**
  - 理由：REQ-21 音频分流的目标页就是现有上传链路（REQ-21 §5.2），保留可零成本承接分流落地；同时从首页 CTA 移除，满足「唯一新建入口」。
  - 代价：需处理提纲链路 `/upload?outline=1` 在新流程下的语义（是否仍从流程内带入，见 REQ-21 §7）。
- **备选：重定向到 REQ-21 流程入口**；若 REQ-21 决定把上传能力完全并入 `/projects/new` 流程，则退化为本条备选。

### 5.2 `/projects/new/outline`

- **建议：重定向到 REQ-21 的流程入口（`/projects/new`）。**
  - 理由：提纲在 REQ-21 中已成为**流程内的一步**（可跳过），不再是独立入口；重定向可兼容旧书签与旧链接，回归面小于直接删除。
  - 代价：其它内部跳转若引用该路由须一并清理；三 CDP 脚本相关断言须同步迁移（§8）。
- **备选：删除该 page（访问 404）。**
  - 代价：旧书签失效；`cdp-req13-crosscut.mjs` 的「未登录直连」断言目标须改为新路由（不得直接删断言，须改指向）。

### 5.3 路由保护与兼容

- 新旧路由均须受 `src/proxy.ts:71-72` 保护：未登录访问 → `/login`（crosscut 断言口径保留，目标路由按裁决结果调整）。
- 重定向须为**服务端 / Next 路由层重定向**（非前端 `useEffect`），避免闪跳与未授权态闪现。

### 5.4 与 REQ-21 的衔接

- 本条只输出「路由去留」的裁决结果；流程内部跳转（基本信息 → 提纲 → 分流）由 REQ-21 定义。
- 提纲工作台「进入 AI 访谈」按钮（`outline-plan-workspace.tsx:489-501`）为 REQ-14 D7=B 的唯一入口；分流上移后的入口唯一性修订由 REQ-21 §6 / §10 ⑥ 与 REQ-14 PRD 互引处理，本条不重复。
