### REQ-14 AI 辅助访谈（AI 主访 + 实时侧写）

- **状态**：D2=A（AI 主访）已拍板，进入开发排期
- **拍板依据**：任 2026-10-03 确认 D2=A AI 主访（PRD §0.1 标「✅ 已选定」），**接受文本模型（deepseek-v4-flash）单轮 3-10s 延迟，中期不要求接入实时语音模型**；原「交互方式待产品方确认 / 开发暂缓」状态自本版起失效。D2 取值语义同日修订：D2=A 由原「人主持 + AI 侧写」改指 **AI 主访**，PRD 正文（按原方案 B 起草）待改稿。
- **PRD**：`docs/PRD_REQ-14_AI辅助访谈.md`（v1.2，本批同步更新）
- **来源**：团队决策 D1 ~ D8 + 任（交互方式待确认）
- **背景**：现有链路是「上传录音 → 讯飞转写 → AI 整理 → 人工复核」，现场访谈缺少实时辅助：主持人看不到提纲覆盖进度、拿不到侧写提示，也无法在访谈结束时立即把音频绑定项目归档。
- **目标范围**：
  - 新增访谈控制台 `/projects/{id}/interview`：实时字幕（Web Speech）+ 录音（Web Audio → WAV）+ 提纲 checklist + AI 侧写区（含负面情绪提示）+ 控制栏（录音 / 暂停 / 结束 / TTS 开关 / 计时）。
  - 新增 3 条 API：`POST /api/projects/ai-interview`（建项目）、`POST /api/projects/{id}/interview/audio`（录音归档）、`POST /api/projects/{id}/interview/sidecar`（侧写抽样）。
  - 入口唯一在提纲工作台「进入 AI 访谈」；结束后复用既有 `process` 链路（讯飞归档 + 整理 → 处理台）。
- **交互方式（已选定，详见 PRD §0.1）**：
  - **A：AI 直接语音主访（✅ 已选定）** —— 1 ~ 2 周；伦理风险高（边界待改稿明确），**当前 LLM 每轮响应 3-10s 的延迟已由任接受，中期不要求实时语音模型**。
  - B：人主持 + AI 实时侧写（已落选；为 PRD 现有正文的起草依据）。
  - C：AI 仅协助准备提纲 + 访谈只录音归档（仅作 10-05 兜底路径，无侧写与情绪提示）。
- **已拍板约束**：
  - D3=A：录音为唯一归档源（WAV 单声道 16kHz/16bit，≈1.9 MB/min、50 分钟上限）。
  - D4=A：仅音频，不做视频采集。D6=A：TTS 默认关闭（开启时抑制字幕回灌）—— 其原注「人主持（AI 不主动提问）」**随 D2 修订作废**，TTS 开关与回灌抑制仍有效，待按方案 A 改稿时复核。
  - D7=B：入口唯一在提纲工作台。D8=C：情绪提示以规则引擎为主、LLM 抽样增强。
  - 建项目 `confidentialityLevel` 默认 `internal`、不弹确认窗，控制台只读（接口层 `PATCH` 已具备能力、UI 未暴露）。
  - 首页与上传页本批不动；上传页「AI 访谈」卡片保持 `disabled`（依据 `interview-upload-form.tsx:662` + `api/projects/route.ts:151-156`）。
- **情绪提示定位修正（任反馈）**：给后台编辑看、只关注负面情绪、**只标注事实不给建议**；新增 sidecar 出参去掉 `guidance`。存量处理台 / 导出的联动改动归 **UI-07**。

## 四、已知局限（现存事实，不随本批次修复）

> 下列为**当前代码事实**中已知的不足，登记备查；除注明外均不在本批次修复。

1. **JSON 单文件存储的并发上限**：项目数据以单文件 JSON 保存，写入侧虽已加固（原子写 + 串行队列 + 损坏隔离 + dev / build 目录隔离，见 §二-2），但并发编辑 / 多写者场景无数据库级保障 → **REQ-17 的后台并发编辑开工前需评估**。
2. **`maskByRules` 的 name 规则无实现分支**：规则选项在 `src/lib/oral-history.ts` 中暴露，但 name 类规则实际不生效。
3. **`isExcerptMatchedByRules` 对地址前缀存在漏报**：以「地址前缀」形式出现的片段可能不被判定命中，导致复核面板漏提示。
4. **存量正面情绪样例与新口径不一致**：现有 `emotionalSignals` 含 notice 级正面情绪（如「幽默与乐观」「輕鬆愉快」），与「只收负面情绪」的新口径不符；**不迁移存量数据**，仅新链路按新口径产出。
5. **提纲 → 上传的携带依赖会话态**：`?outline=1` + `sessionStorage`，跨设备 / 清缓存即丢失 → 由 REQ-15 草稿箱解决。
6. **单通道转写无法做说话人分离**：Web Speech 与讯飞均为单通道，无法区分主持人与受访者（已在 PRD §10 列为不做）。
